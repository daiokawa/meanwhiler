# 広告アーキテクチャ — 「配るのは在庫、選ぶのは代理人」

## 原則
1. **読者のプロファイルは1バイトも外に出ない**。広告フィード(adfeed.json)は全購読者に同一内容が届く静的JSON。
2. **配信≠掲載**。フィードは広告の「在庫リスト」であって掲載指示ではない。各読者のローカルAIが、広告のhints(想定読者ヒント)を読者との会話文脈と照合し、合う時だけ紙面に載せる。**「配信されたが表示されない」が多数派**になるのが正常。
3. 掲載の関門は四つ: 1日1本の上限/文脈との合致/期限(expires)/読者の作法帳(過去に「要らない」と言った種類は出さない)。
4. 表示は「今」でなくてもよい。代理人は話題が来たタイミングで載せてよい(時間差の的確さ)。
5. **開示**は本文末尾の「※これは広告です。」一行(景表法ステマ規制準拠)。

## 自浄作用
hintsを盛って「全員向け」と書いた広告は、どの読者の文脈とも強く合致せず、各地の代理人に弾かれて掲載ゼロになる。**誇大なターゲティング申告=配信されない**。フィード運営者の審査と代理人の目利きの二重フィルタ。

## 経済設計
- **測れるもの**: 購読数(フィード取得数=部数)、成約数(アフィリエイトリンク/クーポン経由で広告主側が計測)
- **測れないもの**: 表示回数、誰が見たか(中央も広告主も知り得ない)
- したがってCPM(表示課金)は存在しない。課金は **成果報酬**(アフィリエイト・料率は市場価格)と **枠掲載料**(「フィードに◯週間載る権利」・実績成約数から逆算)の二本立て。
- 広告主への説明は一行:「**あなたの広告は、読まれる時にしか存在しない**」

## 分散設計(フォークと収益)
- 広告は**既定でオフ**(config.jsonのad_feed_urlが空)。購読は読者の選択。
- 収益はフィード内URLに埋まったアフィリエイトID/成果コードに紐づく。**自分のフィードを立てて自分のIDを埋めれば、収益はその運営者のもの**。広告レイヤーごと分散しており、囲い込みはない。
- フィード運営者の価値=「購読する価値のある在庫の編集権」。

## 公式フィード
- URL: https://raw.githubusercontent.com/daiokawa/meanwhiler-feed/main/adfeed.json
- 出稿希望は meanwhiler-feed リポジトリのIssueまたは運営者へ。

## adfeed.json仕様(v1)
```json
{
  "version": 1,
  "updated": "YYYY-MM-DD",
  "ads": [
    {
      "id": "一意なID",
      "category": "travel|gadget|event|...",
      "hook": "見出し(秘書の提案の声で)",
      "body": "本文2〜3文",
      "url": "リンク(アフィリエイトパラメータ込み)",
      "expires": "YYYY-MM-DD",
      "hints": ["想定読者の文脈語", "..."]
    }
  ]
}
```
